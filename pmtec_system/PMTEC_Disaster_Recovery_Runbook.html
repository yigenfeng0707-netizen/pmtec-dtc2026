1. 系统架构与服务拓扑概览

PMTEC 系统基于 ASDA（Act-Sense-Decide-Adapt）循环构建，采用分布式微服务架构。灾备恢复前需理解以下服务拓扑：

7
Docker 服务实例
4+1
gRPC 节点（主+备）
6
AI 模型文件
2
SQLite 数据库

1.1 服务清单

服务名 容器名 端口 依赖 灾备优先级
War Engine（战争引擎） pmtec-war-engine 50051 SQLite 状态库、DQN/MADDPG 模型 P0 关键
Battle Network（战网络） pmtec-battle-network 50052 War Engine (gRPC HA) P1 高
Application Store（应用存储） pmtec-app-store 50053 SQLite 事件库 P1 高
Plug & Play（即插即用） pmtec-plug-and-play 50054 Battle Network P2 中
War Engine Backup（引擎备份） pmtec-war-engine-backup 50055 共享卷（只读模型） P0 关键
Prometheus（监控） pmtec-prometheus 9090 各服务 /metrics 端点 P2 中
Grafana（可视化） pmtec-grafana 3000 Prometheus 数据源 P3 低

2. 数据备份策略

2.1 备份层级与 RPO/RTO 目标

层级 范围 RPO（数据丢失上限） RTO（恢复时间上限） 保留策略
L1 完整备份 全量 data/ + config + proto 24h 30min 保留 7 份（7 天滚动）
L2 增量备份 当日变更的 .db / .zip / .pt 1h 10min 保留 24 份（小时滚动）
L3 模型快照 data/models/ 全量 0（训练后即时） 5min 永久保留（版本化）
L4 远程副本 L1 备份异地复制 48h 2h 保留 4 份（每周）

2.2 备份执行脚本

L1 完整备份

# 执行完整备份（建议加入 cron: 0 2 * * *）
PROJECT_ROOT="D:/APPs/数字孪生挑战赛/pmtec_system"
BACKUP_DIR="D:/APPs/数字孪生挑战赛/backups"
TIMESTAMP=$(date +%Y%m%d_%H%M%S)
BACKUP_NAME="pmtec_full_${TIMESTAMP}"

# 1. 创建备份目录
mkdir -p "${BACKUP_DIR}/${BACKUP_NAME}"

# 2. 停止写入（不停止服务，使用 SQLite WAL checkpoint）
python -c "import sqlite3; c=sqlite3.connect('${PROJECT_ROOT}/data/persistence/pmtec_state.db'); c.execute('PRAGMA wal_checkpoint(TRUNCATE)'); c.close()"

# 3. 复制数据目录
cp -r "${PROJECT_ROOT}/data" "${BACKUP_DIR}/${BACKUP_NAME}/"
cp "${PROJECT_ROOT}/config.py" "${BACKUP_DIR}/${BACKUP_NAME}/"
cp "${PROJECT_ROOT}/docker-compose.yml" "${BACKUP_DIR}/${BACKUP_NAME}/"
cp -r "${PROJECT_ROOT}/proto" "${BACKUP_DIR}/${BACKUP_NAME}/"

# 4. 生成校验和
cd "${BACKUP_DIR}/${BACKUP_NAME}"
find . -type f -exec md5sum {} \; > checksums.md5

# 5. 压缩
cd "${BACKUP_DIR}"
tar czf "${BACKUP_NAME}.tar.gz" "${BACKUP_NAME}"
rm -rf "${BACKUP_NAME}"

# 6. 清理过期备份（保留最近 7 份）
ls -t "${BACKUP_DIR}"/pmtec_full_*.tar.gz | tail -n +8 | xargs rm -f

echo "[Backup] L1 complete: ${BACKUP_DIR}/${BACKUP_NAME}.tar.gz"

L2 增量备份（每小时）

# 增量备份：仅 SQLite 数据库 + 当日变更文件
PROJECT_ROOT="D:/APPs/数字孪生挑战赛/pmtec_system"
BACKUP_DIR="D:/APPs/数字孪生挑战赛/backups"
TIMESTAMP=$(date +%Y%m%d_%H%M%S)
BACKUP_NAME="pmtec_incr_${TIMESTAMP}"

mkdir -p "${BACKUP_DIR}/${BACKUP_NAME}"

# WAL checkpoint 后复制数据库
python -c "import sqlite3; c=sqlite3.connect('${PROJECT_ROOT}/data/persistence/pmtec_state.db'); c.execute('PRAGMA wal_checkpoint(TRUNCATE)'); c.close()"
cp "${PROJECT_ROOT}/data/persistence/"*.db "${BACKUP_DIR}/${BACKUP_NAME}/"

# 检查是否有新模型文件（1 小时内修改的）
find "${PROJECT_ROOT}/data/models/" -name "*.zip" -o -name "*.pt" | xargs find -mmin -60 2>/dev/null | while read f; do
    cp "$f" "${BACKUP_DIR}/${BACKUP_NAME}/"
done

cd "${BACKUP_DIR}"
tar czf "${BACKUP_NAME}.tar.gz" "${BACKUP_NAME}"
rm -rf "${BACKUP_NAME}"

# 保留最近 24 份
ls -t "${BACKUP_DIR}"/pmtec_incr_*.tar.gz | tail -n +25 | xargs rm -f
echo "[Backup] L2 complete: ${BACKUP_NAME}.tar.gz"

L3 模型快照（训练后执行）

# 训练完成后立即快照模型文件
PROJECT_ROOT="D:/APPs/数字孪生挑战赛/pmtec_system"
SNAPSHOT_DIR="D:/APPs/数字孪生挑战赛/backups/model_snapshots"
TIMESTAMP=$(date +%Y%m%d_%H%M%S)

mkdir -p "${SNAPSHOT_DIR}/${TIMESTAMP}"
cp "${PROJECT_ROOT}/data/models/"*.zip "${SNAPSHOT_DIR}/${TIMESTAMP}/"
cp "${PROJECT_ROOT}/data/models/"*.pt "${SNAPSHOT_DIR}/${TIMESTAMP}/"
cp "${PROJECT_ROOT}/data/models/"*.json "${SNAPSHOT_DIR}/${TIMESTAMP}/"

# 生成模型清单
ls -la "${SNAPSHOT_DIR}/${TIMESTAMP}/" > "${SNAPSHOT_DIR}/${TIMESTAMP}/manifest.txt"
echo "[Backup] L3 model snapshot: ${SNAPSHOT_DIR}/${TIMESTAMP}/"
注意：SQLite WAL 模式下直接复制 .db 文件可能导致数据不一致。备份前必须先执行 PRAGMA wal_checkpoint(TRUNCATE) 将 WAL 日志合并到主数据库，或使用 SQLite 的 .backup 命令做在线热备份。

3. 故障恢复流程

3.1 故障分级与响应矩阵

级别 定义 响应时间 升级阈值
P0 致命 核心仿真引擎宕机、数据丢失、安全证书过期 5 分钟内响应 15 分钟未恢复 → 升级
P1 严重 gRPC 主节点不可用（备节点接管）、AI 模型加载失败 15 分钟内响应 30 分钟未恢复 → 升级
P2 中等 监控/Grafana 不可用、非关键服务离线 1 小时内响应 4 小时未恢复 → 升级
P3 低 单个容器重启、日志告警 4 小时内响应 次日处理

3.2 场景一：gRPC 主节点宕机

故障现象

War Engine 主节点 (pmtec-war-engine, 端口 50051) 健康检查失败，客户端连接超时。

恢复步骤

1确认故障 — 检查健康检查状态：

# 检查容器状态
docker ps -a --filter "name=pmtec-war-engine"

# 检查健康检查日志
docker inspect --format='{{json .State.Health}}' pmtec-war-engine | python -m json.tool

# 手动探测 gRPC 端口
python -c "import grpc; ch=grpc.insecure_channel('localhost:50051'); ch.close(); print('OK')"

2验证 HA 自动切换 — 备节点应已接管：

# 检查备节点状态
docker ps --filter "name=pmtec-war-engine-backup"

# _HAChannelManager 应已自动切换到 backup
# 日志中查找 "failover" 关键字
docker logs pmtec-battle-network 2>&1 | grep -i "failover\|backup\|reconnect"

3重启主节点

# 重启主节点容器
docker restart pmtec-war-engine

# 等待健康检查通过（约 30 秒）
docker inspect --format='{{json .State.Health.Status}}' pmtec-war-engine

# 确认主节点恢复后，流量应自动切回（_HAChannelManager 指数退避重连）
docker logs pmtec-war-engine 2>&1 | tail -20

4验证恢复

# 运行 30 秒快速验证
D:/miniconda3/envs/pmtec-xpu/python.exe -c "
from services.grpc_server import PMTECEngine
e = PMTECEngine()
e.start_simulation('recovery_check', 30, seed=42)
import time
while e._running: time.sleep(1)
s = e.get_state_dict()
print(f'Entities: {s[\"total_entities\"]}, Tracks: {s[\"active_tracks\"]}')
print('RECOVERY OK' if s['total_entities'] > 0 else 'RECOVERY FAIL')
"

3.3 场景二：SQLite 数据库损坏

故障现象

pmtec_state.db 查询报错 database disk image is malformed，仿真状态无法持久化。

恢复步骤

1确认损坏范围

# 完整性检查
python -c "
import sqlite3
db = 'D:/APPs/数字孪生挑战赛/pmtec_system/data/persistence/pmtec_state.db'
conn = sqlite3.connect(db)
cursor = conn.execute('PRAGMA integrity_check')
result = cursor.fetchone()
print(f'Integrity: {result[0]}')
conn.close()
"

2尝试 WAL 恢复

# 如果 integrity_check 返回 "ok"，可能是 WAL 文件损坏
# 删除 WAL 和 SHM 文件，让 SQLite 重新生成
PROJECT_ROOT="D:/APPs/数字孪生挑战赛/pmtec_system"
rm -f "${PROJECT_ROOT}/data/persistence/pmtec_state.db-wal"
rm -f "${PROJECT_ROOT}/data/persistence/pmtec_state.db-shm"

# 再次检查
python -c "import sqlite3; c=sqlite3.connect('${PROJECT_ROOT}/data/persistence/pmtec_state.db'); print(c.execute('PRAGMA integrity_check').fetchone()[0]); c.close()"

3从备份恢复（如果步骤 2 无效）

# 找到最近的增量备份
BACKUP_DIR="D:/APPs/数字孪生挑战赛/backups"
LATEST=$(ls -t "${BACKUP_DIR}"/pmtec_incr_*.tar.gz | head -1)
echo "Restoring from: ${LATEST}"

# 解压备份
cd /tmp
tar xzf "${LATEST}"

# 替换损坏的数据库
PROJECT_ROOT="D:/APPs/数字孪生挑战赛/pmtec_system"
cp /tmp/pmtec_state.db "${PROJECT_ROOT}/data/persistence/pmtec_state.db"

# 验证恢复
python -c "import sqlite3; c=sqlite3.connect('${PROJECT_ROOT}/data/persistence/pmtec_state.db'); print('Tables:', [t[0] for t in c.execute('SELECT name FROM sqlite_master WHERE type=\"table\"').fetchall()]); c.close()"

4验证仿真状态

# 启动 30 秒仿真，验证状态写入正常
D:/miniconda3/envs/pmtec-xpu/python.exe -c "
from services.grpc_server import PMTECEngine
e = PMTECEngine()
e.start_simulation('db_recovery', 30, seed=99)

print(f'Snapshots: {s.get(\"snapshot_count\", \"N/A\")}')

审计日志归档

# 归档 90 天前的审计记录
python -c "
import sqlite3, time, shutil
db = 'D:/APPs/数字孪生挑战赛/pmtec_system/data/persistence/audit_log.db'
archive = 'D:/APPs/数字孪生挑战赛/backups/audit_archive.db'
cutoff = time.time() - 90*86400
conn = sqlite3.connect(db)
count = conn.execute('SELECT COUNT(*) FROM audit_log WHERE timestamp < ?', (cutoff,)).fetchone()[0]
if count > 0:
    # 导出旧记录到归档库
    aconn = sqlite3.connect(archive)
    aconn.execute('CREATE TABLE IF NOT EXISTS audit_log AS SELECT * FROM audit_log WHERE 1=0')
    rows = conn.execute('SELECT * FROM audit_log WHERE timestamp < ?', (cutoff,)).fetchall()
    aconn.executemany('INSERT INTO audit_log VALUES ({})'.format(','.join(['?']*len(rows[0]))), rows)
    aconn.commit()
    conn.execute('DELETE FROM audit_log WHERE timestamp < ?', (cutoff,))
    conn.commit()
    aconn.close()
    print(f'Archived {count} audit records to {archive}')

6. 应急联系与升级流程

6.1 升级路径

阶段 触发条件 动作 时限
L1 自动恢复 容器不健康 / gRPC 超时 Docker 自动重启 + HA 故障转移 0-5 分钟
L2 运维介入 自动恢复失败 / P0 告警 人工按 Runbook 执行恢复 5-30 分钟
L3 专家介入 数据损坏 / 安全事件 从备份恢复 + 安全审计 30 分钟-2 小时
L4 全量重建 宿主机故障 / 数据全失 L4 远程副本恢复全栈 2-4 小时

6.2 恢复验证清单

每次故障恢复后，必须完成以下验证才能标记为"已恢复"：

  • 全部 7 个容器状态为 healthy
  • gRPC 端口 50051-50054 可达，0 错误
  • SQLite integrity_check 返回 "ok"
  • DQN + MADDPG + IQL 模型加载成功（6/6）
  • 30 秒快速仿真通过（entities > 0, tracks > 0）
  • Monte Carlo 5 episode 拦截率 >= 70%
  • Prometheus 所有 target 为 UP
  • 审计日志正常写入（恢复后 > 0 条）
  • 备份任务正常执行（手动触发一次 L2）
