GAP 01

GAP 02
安全与认证体系
P0 关键▶
现状
gRPC/REST API 无认证、无 TLS、无 RBAC、无审计，完全裸奔
目标
mTLS 双向认证 + JWT 令牌 + 三级 RBAC + 不可篡改审计链
  • 生成 CA/Server/Client 证书，gRPC 添加 SSL/TLS ContextW1-W2
  • JWT 令牌签发端点 + Token 校验拦截器 + 刷新机制W2-W3
  • RBAC 三级角色：指挥员(全权) / 操作员(运行级) / 观察员(只读)W3
  • 操作审计日志：结构化记录 + Hash 链防篡改 + 查询 APIW4
  • 证书自动轮换机制（30 天到期前自动续签）W4
✓ 验收标准
无 JWT 令牌的请求被拒绝；RBAC 阻断越权操作；审计日志完整记录全部 API 调用
依赖: grpc_server.py / proto / OpenSSL
风险: 中
工作量: 4 周

风险缓解策略

最高风险：多智能体 RL 不稳定
多智能体 RL 训练不稳定是公认难题。缓解：(1) 先用 IPPO 做基线（稳定性优于 MADDPG）；(2) 超参网格搜索；(3) 若 500K 步不收敛，回退单智能体 DQN + 规则化分工。
中风险：Proto 契约兼容
安全认证需要扩展 proto 定义。缓解：(1) 仅新增字段，不修改/删除已有字段；(2) 生成向后兼容代码；(3) 集成测试覆盖旧客户端调用。
低风险：工期可控
P0 两项可完全并行（安全认证 + 验证框架无依赖）。P1 中 GAP 03/04/05 有 1 周重叠但互不依赖。P2 两项并行。总缓冲约 1.5 周。
