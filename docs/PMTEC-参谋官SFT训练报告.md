# PMTEC 参谋官自有模型 SFT 训练报告（里程碑 1）

> 依据：《端侧大模型自主训练技术路线》（冯亦根，2026-10）阶段二 SFT ｜ 训练日期：2026-10-24
> 训练环境：超算云并行智算云实例 ecs-mlzsy（RTX 4090 24GB ×2，实例 36.103.199.151，按量计费）
> 基座：Qwen2.5-7B-Instruct（实例本地 /data/models，与 vLLM 服务共存）
> 诚实声明：本报告全部数字来自训练日志与语料实测；定性测试的失败案例如实收录（见第四节）

## 一、执行摘要

路线图阶段二首个里程碑落地：以 PMTEC 自有语料（174 条，全部来自仓库真实产物）对 Qwen2.5-7B-Instruct 完成 QLoRA→bf16 LoRA 监督微调，训练 80 步 / 376 秒收敛，LoRA 适配器（170MB）经 vLLM 以 OpenAI 兼容接口对外服务。定性测试显示：**诚实拒答边界与出处引用风格已习得**（满分项），**裸问答的覆盖外细节仍会幻觉**（如实记录，缓解方案见第五节——部署态按系统设计走结构化上下文注入，不依赖裸记忆）。

## 三、训练配置与结果

| 项 | 值 |
|----|-----|
| 方法 | LoRA（r=16, α=32, dropout 0.05, 七投影全挂）——**bf16 底座，未用 4bit** |
| 弃用 QLoRA 原因 | bitsandbytes 0.50.2 在 torch 2.6 + RTX 4090 的 dequant 触发 CUBLAS_STATUS_INTERNAL_ERROR（实测三次复现）；bf16 全精度 LoRA 在 24GB 内可容纳且质量更优 |
| 训练 | 80 步 / 8 epochs / 376.9 秒；有效批 16（batch 1 × 累积 16）；lr 2e-4 cosine |
| 显存 | 峰值 ~23GB（7B bf16 权重 15.2GB + 梯度检查点激活 + 152K 词表 logits 张量）；单卡放不下时 device_map=auto 双卡拆分会触发 4.51 跨设备 loss bug，故固定单卡 + MAXLEN 512 + expandable_segments |
| 产物 | `/data/out/sft_pmtec_lora/adapter`（170MB safetensors）+ training_meta.json |
| train_loss | 0.9956（末值） |

## 五、缓解与下一里程碑

1. **部署态缓解（已内建）**：PMTEC 参谋官的生产用法是结构化上下文注入——llm_analyst 将孪生摘要/事件流字段注入提示词，模型只做组织与解读，数字取自注入内容而非记忆。裸问答幻觉不影响该模式。
2. **语料飞轮（路线图 §6.2）**：v1 语料 174 条 → 扩容方向：逐基地全字段 QA、事件流滑动窗口解读对、按 26 测试断言生成的工程 FAQ；目标 v2 ≥ 500 条。
3. **引用式评测门禁**：评测从"像不像"升级为**引用命中率**——生成文本中的数字必须能在注入上下文或仓库产物中回查，命中率达标方可发布（路线图 §6）。
4. **DPO 偏好对齐（阶段三）**：以"编造数字被驳回"的负例与"引用式正例"构造偏好对。

## 六、集成说明

参谋官切换自有模型：vLLM 已以适配器服务（`--enable-lora --lora-modules pmtec-officer=...`，端口 8000，模型名 `pmtec-officer`）；PMTEC llm_analyst 为 OpenAI 兼容 HTTP 接入，配置 base_url 指向实例 8000 端口即可切换（当前生产仍为外部 API，切换属运维操作）。

### 引用式评测门禁（首次正式基线，scripts/eval_citation_gate.py）

| 指标 | 基座（无微调） | SFT v2 |
|------|---------------|--------|
| 事实锚点命中率（8 事实题） | **25%**（2/8） | **50%**（4/8，翻倍） |

陷阱题（"D-SPEAR 场景全量实体数""2027-04 校准偏差""第 13 号案例"等系统产物中不存在的伪前提）两个模型都 100% 编造——SFT 对**未覆盖前提的幻觉抑制无效**，这是本轮最重要的诚实发现。

### 结论与下一里程碑

1. 语料飞轮对**已覆盖事实的召回**有效（锚点翻倍），对**未覆盖前提的幻觉抑制无效**；
2. 下一里程碑（按序）：a) 语料 v3 加入「陷阱拒答对」族（伪前提→需回查产物话术，本轮陷阱题全部转为训练负例）；b) 部署态坚持结构化上下文注入（数字取自注入内容而非记忆，PMTEC 参谋官架构已内建）；c) 引用命中率门禁纳入发布流程；
3. 实例现状：vLLM 挂 v2 适配器服务中（端口 8000，模型名 pmtec-officer / pmtec-officer-qwen25-7b），按量计费至 10-14。

## 里程碑 3：去重 + 陷阱拒答族实验（2026-10-24，负结果如实记录）

### 实验

- 语料 v3：352 条（去重守卫后唯一对；v2 的 1,926 条实含大量重复——逐基地/逐站点族的补丁重试导致段落重复注入）
- 陷阱拒答族 16 对 ×4 上采样（伪场景名/伪日期/伪指标/真实实体配伪属性四类 + 真假混合判别对）
- 同配置重训：176 步 / 527.7 秒 / train_loss 1.0235

### 引用门禁结果（gate_v3.json）

| 指标 | 基座 | SFT v2 | **SFT v3** |
|------|------|--------|-----------|
| 事实锚点命中率 | 25% | **50%** | **25%（回归）** |
| 陷阱题幻觉率 | 100% | 100% | 100%（生成态未翻转） |

### 发现（科学结论，负结果也是结果）

1. **v2 的"重复"实为事实上采样**：v1→v2 的 11 倍膨胀中，重复条目让每个事实获得多遍训练——这正是锚点命中率翻倍的机制。v3 去重删除了该上采样效应，召回回归到基线。教训：**窄领域事实注入场景下，重复=有效训练信号**，"去重=干净"的直觉在此不成立。
2. **陷阱拒答经 SFT 上采样未在生成态翻转**（16 对 ×4 仍 100% 编造）：行为对齐（拒绝编造）靠 SFT 模式匹配不足以稳定习得——这正是路线图将 DPO 偏好对齐列为阶段三的原因（需要偏好对比信号而非模仿信号）。
3. **部署态不受影响**：生产参谋官为结构化上下文注入模式（数字取自注入的孪生摘要而非模型记忆），陷阱幻觉不构成该模式下的交付风险；裸问答模式已由评测门禁显式标注不可信。

### 服务状态与迭代决策

- vLLM 已恢复服务 **v2 适配器**（最优检查点）：端口 8000，模型名 pmtec-officer / pmtec-officer-qwen25-7b
- 迭代决策：SFT 路线在当前语料规模下已饱和（v2 为最优检查点）；后续提升走路线图阶段三（DPO）与结构化注入/RAG，不再单纯堆 SFT 语料
- 证据：gate_v3.json（实例 /data/sft/）+ 训练日志 train_v3.log（527.7s 完整收敛记录）
